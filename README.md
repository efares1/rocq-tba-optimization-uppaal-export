# Mechanically Verified Optimization and UPPAAL-Oriented Transformation of Timed Büchi Automata

Source, proofs, tool, and evaluation of the IEEE Access article.
It builds on the earlier article "A Mechanically Verified Translation of
MTL<sub>0,∞</sub> into Timed Büchi Automata", whose repository is
https://github.com/efares1/rocq-mtl-to-tba-translation ; both use
the same Rocq foundation (`SHARED_FOUNDATION_MANIFEST.txt`,
`scripts/check_shared_foundation.sh`).

## Scope

The preservation theorems hold for every TBA represented by the
formula-indexed clock interface, independently of whether the automaton was
generated by the MTL translator: clocks are named by the timed subformulas of
a fixed formula, which serves only as a supply of clock names. Optimization
(`optimize_accepts`) preserves the timed-word language for every finite number
of rounds; export (`export_accepts`, `export_all_accepts`) preserves it and
yields conjunctive guards and invariants. The end-to-end theorems
`MTL_to_exported_correct_with`, `MTL_to_exported_correct0_with` (zero-initialized
clocks, under the verified `init_free` check), and
`MTL_to_exported_correct0_recur_weak_with` (the tool's default front end)
compose these results with the translation theorem of that article, which is cited,
not re-proved.

## Reproduction

```
cd proof && make COQC=<path>/coqc     # proofs, extraction to ../tool/src/optim.ml
<path>/coqc -w -deprecated-missing-stdlib Audit_Revision_20261010.v
cd ../tool && dune build              # OCaml 4.14+ or 5.x, dune, menhir; Spot 2.16 at run time
cd ../evaluation
bash run_full_eval.sh                 # generated F/R/N group (WSL/Linux)
bash run_synthetic_ablation_v2.sh     # synthetic suite and leave-one-out (from the repository root)
bash run_boundary_tests.sh && python3 check_boundaries.py boundary_out
```

PDFs: `build.ps1` (Windows) or `pdflatex`/`bibtex` on `paper2` and `paper2_supp`.

## Trusted components

Outside the Rocq proofs: Spot and the LBTT reader (the translation's backend
contract), parsing and printing (DOT, UPPAAL XML), extraction, floating-point
realization of bounds, any adapter that converts an external automaton into
the Rocq representation, and the interpretation of the printed model by UPPAAL
or TChecker. UPPAAL results in the article were rerun on 2026-10-11 with the installed
UPPAAL 5.0.0 verifier (8/8 verdicts identical to the archive).
